# 真实工作流与不可变发布版本

本文描述真实工作流及版本执行。普通 MySQL 节点支持多语句读写，见 [SQL 执行说明](mysql-query.md)；库存专用发布语义见 [库存日结与调度](inventory-scheduling.md)。

工作流支持本机单用户的 DAG 执行。工作流每次只执行一个节点，各普通 MySQL 节点可逐条执行并提交 SQL 脚本；连线表达执行依赖，不直接传递查询结果。包含普通写入节点的工作流不自动失败重试。开发调试和已发布版本运行沿用节点绑定的业务数据源，没有另外创建生产数据库。

## 从示例开始

在“示例代码”打开 **MySQL 订单查询工作流**。图中有“订单概览 → 城市统计 / 订单状态统计”三个真实节点。

1. 点击 **开发调试**。界面先保存工作流和引用节点的相关草稿，提交父、子版本校验，执行期间显示只读运行画布。
2. 在“节点与结果”点击节点，查看当次日志、结果、代码快照。显示的图和版本属于本次运行，后续编辑不影响它。
3. 点击 **发布**，填写说明，再点击 **发布新版本**，得到 R1。发布本身不会运行 SQL。
4. 修改并保存节点代码只产生新的 V 版本。点击 **运行已发布版本 → 运行 R1**，仍执行发布时的代码；此操作不会保存当前草稿。
5. 再发布得到 R2，可以分别运行 R1、R2。手动运行历史版本不会改变最新发布版本。

新建工作流时，在右侧“运行配置”显式选择“真实手动工作流”，再“导入已有节点”。只支持同空间、未删除、已绑定数据源的真实 MySQL 节点。直接从类型库加入但未绑定开发对象的占位节点必须先替换为真实引用。旧工作流没有显式配置时继续模拟。

顶部“更多 → 发布记录”展示当前空间的全部发布。源工作流或子节点移到回收站后，仍可在这里查看并运行旧发布。旧模拟发布仅供查看，不能转换为可执行版本。

## 保存、发布与凭据

- V 是开发对象保存版本；R 是一个工作流的完整发布版本。发布包由后端读取已保存内容生成，包含整张图、每个图节点的代码、配置、V 版本和数据源绑定，不接受客户端提供的执行快照。
- 调试、发布捕获点击时的相关草稿，按对象去重保存；任何保存失败或父子版本冲突都不创建运行/发布。已完成的单对象保存不回滚，其他草稿仍保留。保存过程中继续输入的内容保留为下一次草稿。
- 发布版本只追加、不可覆盖，无修改或删除接口，不使用可修改的通用操作记录表。
- 发布固定数据源 ID、地址、端口、数据库与账号；运行时使用该数据源的当前密码。密码轮换无需重新发布；目标身份改变则返回 `DATASOURCE_BINDING_CHANGED`，需恢复原连接或重新发布。
- 每次运行准备后固定本次连接配置。密码和密文不进入发布包、日志、运行历史或接口响应；历史只显示公开连接信息。

## 执行与停止

所有节点预检成功后，在一个事务内写入父运行和全部子运行快照，事务提交之后才启动查询；后方节点校验失败不会导致前面的查询提前执行。

子状态：`WAITING → QUEUED → RUNNING → SUCCESS / FAILED / CANCELLED`。依赖失败、超时或资源队列拒绝会使下游 `SKIPPED`，独立分支继续；全部分支结束后父工作流汇总为成功或失败。所有直接上游成功才会运行节点，同时就绪时按图的节点顺序执行。同一开发对象可以由多个图节点引用，每个图节点分别执行并保存结果。

“停止整个流程”停止待依赖、排队和执行中的任务，保留已有成功/失败结果；不允许单独停止工作流中的子任务。重复停止幂等，取消后不会再启动下游。

服务重启将未完成父子运行标记 `FAILED / SERVICE_RESTARTED`，不自动续跑。已完成的结果、不可变发布包和运行快照继续保留。

默认每图最多 100 个节点，最多 8 个活动工作流，分别由 `studio.workflow.max-nodes`、`studio.workflow.max-active` 配置。所有查询共用现有 MySQL 有界线程池，每个节点继承整次脚本超时、业务库边界校验和结果上限。

## API

统一前缀 `/api/v1`。

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/runs` | 单节点兼容原协议；真实工作流携带 `objectId`、`expectedVersion`、`expectedNodeVersions` |
| POST | `/workflows/{id}/releases` | `expectedVersion`、`expectedNodeVersions`、`note`，返回发布摘要 |
| GET | `/workflow-releases?workspaceId=&workflowId=` | 发布摘要列表；省略 workflowId 查看整个空间 |
| GET | `/workflow-releases/{id}` | 发布元数据与完整 `bundle` |
| POST | `/workflow-releases/{id}/runs` | 从指定发布包创建运行；不读取开发对象 |
| GET | `/runs/{id}/nodes` | 子运行摘要，包含 `graphNodeId`、`parentRunId` 和子运行 ID |
| GET | `/runs/{id}`、`/runs/{id}/results` | 原有日志、快照及分页结果接口，支持子运行 |
| POST | `/runs/{id}/stop` | 停止顶层运行；对子运行返回 `STOP_PARENT_WORKFLOW` |

`expectedNodeVersions` 为开发对象 ID 到 V 版本的映射，重复引用只需一项。运行来源为 `executionSource=DEVELOPMENT|RELEASE`；发布运行父子记录均带 `releaseId`、`releaseNo`。工作流 provider 为 `WORKFLOW`，子查询为 `MYSQL`。

`/runs` 数组、分页及统计默认仅返回顶层运行，子任务通过 `/nodes` 查询，避免重复统计。

## 迁移与验证

V3 在 `dw_run` 新增父运行和图节点关系，并创建 `dw_workflow_release`。既有运行关系列为 NULL，不改变历史内容。升级前先运行 `scripts/backup-metadata.ps1` 并确认成功；不要删除数据库或重跑基线。原加密密钥与本地配置继续沿用。

后端 `mvn.cmd test` 覆盖真实查询、依赖推进、发布隔离、取消、事务回滚、凭据边界、迁移和恢复。测试使用随机空间/临时迁移库，只清理自身数据。前端 `npm.cmd test` 覆盖相关草稿捕获、重复引用、部分保存失败和继续编辑；另外运行类型检查、构建与浏览器验收。
