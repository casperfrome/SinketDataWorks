# 实时数据开发与运维预览

“实时数据开发”位于左侧“离线数据开发”入口下方。原“数据开发”改名为“离线数据开发”，已有离线任务、真实 SQL 执行、工作流、发布和 Cron 调度保持原有机制。

实时模块目前只实现前端工作台。任务、草稿、发布版本和模拟作业使用独立的数据结构与浏览器存储，没有新增实时后端接口，也没有连接 Flink 集群。数据库数据源列表、表和字段导入复用已有只读接口。

## 数据源与连接器

所有连接仍在原“数据源”入口维护，可按 MySQL、Doris、Kafka 筛选。MySQL / Doris 继续由后端保存和测试连接；Kafka 配置保存在当前浏览器的对应工作空间，“配置检查”只校验地址和认证字段，不发起 Kafka 连接测试。

Kafka 支持 Bootstrap Servers、PLAINTEXT / SASL_PLAINTEXT / SASL_SSL，以及 PLAIN / SCRAM-SHA-256 / SCRAM-SHA-512。多个 Broker 使用逗号分隔，例如 `broker-1:9092,broker-2:9092`。SASL 密码仅保留在当前页面会话内，刷新页面后需重新填写；密码不会写入浏览器持久存储、发布快照或自动生成的 DDL。

任务内分别配置 Source 和 Sink，可添加多条绑定：

| 位置 | 连接器 | 主要配置 |
| --- | --- | --- |
| Source | Kafka | 数据源、Topic、Consumer Group、起始位点、JSON / CSV 格式 |
| Source | MySQL CDC | 数据源、物理表、启动模式、Server ID / 范围、服务器时区 |
| Sink | Kafka | 数据源、Topic、追加或 Upsert；当前 Upsert 配置器使用主键及 JSON |
| Sink | MySQL JDBC | 数据源、物理表、追加或按主键更新 |
| Sink | Doris | 数据源、物理表、FE HTTP 地址、表模型、同步删除、Label 前缀 |

逻辑表名用于 Flink SQL 的 `FROM` / `INSERT INTO`，物理表或 Topic 用于描述外部来源和目标。切换连接器保留字段结构，并重置不适用的连接配置。

MySQL CDC 当前配置器要求主键，Server ID 范围须覆盖来源并行度；无主键表的 chunk key 配置暂未提供。Doris 使用 FE HTTP 地址，支持 `http://fe-host:8030` 或 `fe-host:8030`，不能填 SQL 查询端口。同步删除要求 Unique 表模型及目标主键。

## 字段、Watermark 与 SQL

点击“编辑字段”配置字段名、Flink 类型、可空属性和主键，也可增删字段。主键字段不可为空。选择已有 MySQL / Doris 物理表后，可“导入字段”；已有结构替换前会要求确认，未识别的数据库类型需手动选择 Flink 类型。异步返回的元数据不会应用到已切换的数据源、物理表或任务。

Source 可选择 `TIMESTAMP(3)` 或 `TIMESTAMP_LTZ(3)` 字段作为事件时间，并设置非负的 Watermark 延迟秒数。未选择事件时间时不生成 Watermark。

“预览 DDL”根据连接配置生成 `CREATE TABLE` 结构。自动生成内容引用数据源 ID，省略密码；需要认证的连接器仍待后端注入完整凭据，因此结构预览不能直接执行。

“插入 DDL”在处理 SQL 前插入带绑定标记的生成块。再次插入同一绑定时显示差异，只更新对应生成块，保留其他手写 SQL。手动破坏、嵌套或重复生成块标记后，需要修复标记才能更新该块。连接配置变化不会自动重写编辑器中的 SQL，应重新预览并插入。

处理逻辑直接在 Monaco 编辑器编写，例如：

```sql
INSERT INTO target_orders
SELECT order_id, amount, event_time
FROM source_orders;
```

“配置检查”检查数据源匹配、字段、连接器选项及运行参数。它不检查 Flink SQL 语义、集群兼容性、真实连接权限或外部表能力。通用 SQL 格式化器无法识别的 Flink 语法会保留原文并提示。

## 保存、发布与实时运维

实时内容按工作空间保存在当前浏览器，任务切换、模块切换和空间切换互相隔离。草稿会独立保留，刷新后可恢复；点击“保存”确认当前任务内容。关闭带草稿的标签页时，可保存并关闭、丢弃并关闭或取消。

默认运行配置为并行度 `1`、Checkpoint 间隔 `60` 秒、失败重启次数 `3`、重启等待 `10` 秒。运行配置作为发布快照的一部分保存。当前故障演示采用手动重启或恢复，不执行真实 Flink 重启策略。

发布前检查配置，发布时一并保存当前修改，生成任务独立的 R 版本快照。快照包含 SQL、Source / Sink、字段及运行配置；后续修改草稿或发布新版本不会改动旧快照，也不会自动升级运行中的模拟作业。

在模块内切换到“实时运维”：

1. 选择已发布版本并点击“启动”，演示作业进入启动中、运行中。
2. 点击任务查看运行指标、日志、作业配置、Checkpoint、Savepoint 和操作历史。吞吐、延迟与 Checkpoint 均为前端模拟数据。
3. 运行时点击“生成 Savepoint”，得到 `mock://savepoints/...` 演示记录；它不指向真实状态文件。
4. 点击“停止”，等待已停止后可启动其他发布版本；“重启”保留当前作业的发布版本。
5. “恢复启动”只能选择当前恢复版本的 Savepoint，切换版本会清空所选保存点。
6. 运行中的作业详情提供“模拟故障”，确认后进入失败状态，可手动重启或从同版本 Savepoint 恢复。

一项任务同时只有一个活动模拟作业。实时运维与原“调度运维”独立，不产生离线运行、Cron 计划、补数或真实 Kafka / Doris 写入。

实时开发快捷键：`Ctrl+S` 保存、`F8` 前往运维、`F9` 停止当前任务的模拟作业、`Shift+Alt+F` 格式化。快捷键不会操作后台保留的离线编辑任务。

## 存储边界与验证

浏览器存储按工作空间区分，使用带版本的 `sinket-realtime:v1:<workspaceId>` 键。配置不会同步到另一台设备、另一个浏览器或不同站点地址，也不包含在元数据库备份中。清除站点存储会删除本地任务、草稿、发布和模拟记录。

保存失败时保留草稿和页面内存，界面显示存储错误；保存、发布、启动等动作须持久化成功后才提交。损坏或不支持版本的原存储内容不会被静默覆盖。出现存储错误时先保留页面并按界面提示处理，恢复可用存储后重试。

在 `frontend` 目录运行类型检查、规则测试及构建：

```powershell
npm.cmd run typecheck
node --test tests/realtimeModel.test.ts tests/realtimeDDL.test.ts tests/realtimeStore.test.ts
npm.cmd run build
```

这些测试覆盖连接器配置规则、字段类型转换、发布快照隔离、DDL 生成与标记替换、模拟状态转换、Savepoint 版本匹配、工作空间存储隔离，以及写入失败保留草稿和阻止重复提交。完整前端测试使用 `npm.cmd test`。

浏览器验收应分别检查：深浅主题和窄屏配置面板；多任务草稿与刷新恢复；数据库字段异步导入；手改 SQL 后更新单个 DDL 块；发布 R1 后修改草稿并启动 R1；R2 不替换运行中的 R1；停止、重启、同版本 Savepoint 恢复与模拟故障；切换空间和模块后草稿、离线运行与快捷键互不干扰。Kafka 连接及 Flink SQL 执行需要后续后端接入后的专门验收。
